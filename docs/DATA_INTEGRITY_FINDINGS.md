# Data Integrity Findings — Critical

**Date:** March 23, 2026
**Severity:** Critical — core data does not match authoritative sources
**Status:** Open — requires data pipeline rebuild

---

## Problem Statement

The three Phase 1 audited JSON files that power every calculation in the app — demographics, property, and socioeconomic — contain data values that **do not match** the U.S. Census Bureau's American Community Survey (ACS) data as published through the City of Austin Demographics Hub.

These files were generated by a Gemini AI audit pipeline that was intended to normalize field names across census tracts. However, the pipeline appears to have **generated estimated values** rather than pulling actual ACS data, resulting in systematic inaccuracies across all 269 census tracts.

Every metric displayed in the app — DVI scores, demographic charts, economics cards, triage rankings, comparison narratives — is computed from this data. **If the underlying data is wrong, every downstream calculation is unreliable.**

### How the data was generated

The original census GeoJSON (`archive/data/udp_austin.geojson`) contains only tract numbers and gentrification typology — **no demographic, property, or socioeconomic values**. The three Phase 1 JSON files were produced by:

1. `scripts/auditRunner.js` — sent each tract's region_id to the Gemini 2.5 Flash API
2. Gemini was prompted to "audit and normalize" demographic data for each tract
3. Gemini generated plausible-looking values with audit metadata (source fields citing "US Census 2020", "ACS 5-Year 2016–2020", etc.)
4. The returned values were written to the Phase 1 JSON files as-is

**The audit_source metadata claims "US Census 2020" and "ACS 5-Year" as sources, but the actual values don't match those sources.** The AI generated estimates that look reasonable in isolation but diverge significantly from authoritative data.

### Audit flag analysis

Of 4,811 demographic rows:
- 3,446 (72%) flagged `INTERPOLATED` — values generated between known years
- 2,937 (61%) flagged `NEW_FIELD_ESTIMATED` — fields where no source data existed
- 1,162 (24%) flagged `CORRECTED` — values adjusted by the AI pipeline
- 860 (18%) flagged `TRACT_MISMATCH` — potential geographic misalignment
- Only 12,606 of 39,256 field-level confidence ratings are "high" (32%)

## Recommended Re-Audit Plan

### Option A: Direct ACS Pull (Recommended)

Pull data directly from the Census Bureau API or the COA Hub ArcGIS Feature Service for each available ACS vintage.

**Step 1: Identify available ACS vintages**

| ACS Vintage | Covers Years | Census API Table | COA Hub Layer |
|-------------|-------------|-----------------|---------------|
| ACS 2006–2010 | 2010 snapshot | B01003, B19013, B25077, etc. | May not be on Hub |
| ACS 2015–2019 | ~2017 snapshot | Same tables | May not be on Hub |
| ACS 2017–2021 | ~2019 snapshot | Same tables | TractsACS21 (layer 75) |
| ACS 2019–2023 | ~2021 snapshot | Same tables | TractsACS23 (if published) |
| Census 2020 Decennial | 2020 exact | P1, P2, H1 | Separate dataset |
| Census 2010 Decennial | 2010 exact | P1, P2, H1 | Separate dataset |
| Census 2000 Decennial | 2000 exact | P001, P003 | Separate dataset |
| Census 1990 Decennial | 1990 exact | P001, P006 | Separate dataset |

**Step 2: Build a fetch script**

```javascript
// scripts/fetch_acs_data.cjs
// Pulls ACS 5-year data from Census Bureau API for Travis County tracts
//
// Census API: https://api.census.gov/data/{year}/acs/acs5
// Geography: tract:*&in=state:48&in=county:453
//
// Required tables:
//   B01003_001E  — Total population
//   B01002_001E  — Median age
//   B19013_001E  — Median household income
//   B25077_001E  — Median home value
//   B25064_001E  — Median gross rent
//   B03002_003E  — White non-Hispanic
//   B03002_004E  — Black non-Hispanic
//   B03002_006E  — Asian non-Hispanic
//   B03002_012E  — Hispanic/Latino
//   B17001_002E  — Population below poverty
//   B25003_002E  — Owner-occupied housing units
//   B25003_001E  — Total occupied housing units
//   B25070_010E  — Renter-paying 30%+ (rent burdened)
//   B05002_013E  — Foreign-born population
//   B01001_020E + ...  — Population 65+
//
// API key: https://api.census.gov/data/key_signup.html
//
// Output: data/phase1_output/acs_{vintage}_demographics.json
//         data/phase1_output/acs_{vintage}_property.json
//         data/phase1_output/acs_{vintage}_socioeconomic.json
```

**Step 3: Map Census tracts to region_ids**

Use the `tractce22` → `region_id` mapping from the GeoJSON to join Census API responses to our region system. The mapping exists in `archive/data/udp_austin.geojson` (269 features with `tractce22` and matching geometry order to `final_updated_regions.js`).

**Step 4: Handle missing years**

- Decennial Census (1990, 2000, 2010, 2020) provides population and race counts only
- ACS 5-year provides income, housing, education, poverty (available ~2005 onward)
- Pre-2005: only decennial data available — flag as lower confidence
- Intermediate years: linear interpolation flagged as `INTERPOLATED`

**Step 5: Replace Phase 1 JSON files**

Write the fetched + interpolated data to the same three JSON files with the same field names. The downstream pipeline (`auditedData.js`, `auditedDvi.js`, `interim_*.js`) will recompute automatically.

**Step 6: Validate**

Compare a sample of tracts against the COA Hub to confirm values match within ACS margin of error (typically ±5–10% for tract-level estimates).

### Option B: Pull from COA Hub Feature Service

If the Census API is too complex, the COA Hub Feature Service provides pre-processed ACS data for Travis County tracts:

```
GET https://services.arcgis.com/0L95CJ0VTaxqcmED/arcgis/rest/services/TractsACS21/FeatureServer/75/query
  ?where=1=1
  &outFields=GEOID20,TRACTCE20,NAME20,tot_popE,median_ageE,perc_NH_WhiteE,perc_NH_BlackE,perc_HispanicE,perc_NH_AsianE,median_HHincomeE,median_home_valueE,perc_povertyE,perc_65plusE,perc_uninsuredE
  &f=json
  &returnGeometry=false
  &resultRecordCount=2000
```

This gives one ACS vintage (2017–2021). Repeat for other vintages if available on the Hub.

**Limitation:** The Hub may only have 1–2 ACS vintages. For historical data (1990, 2000, 2010), the Census Bureau API is required.

### Option C: Hybrid Approach

1. Pull 2020 and 2023 ACS data from the COA Hub (verified, pre-processed)
2. Pull 1990, 2000, 2010 decennial data from Census Bureau API
3. Interpolate intermediate years
4. This gives verified anchor points at every decade + recent ACS

## What NOT to Change

- **GeoJSON polygons** (`data/final_updated_regions.js`) — geometries are correct, only the `region_name` property had issues (already addressed)
- **Business data** (`data/businesses.js`) — community-sourced, not Census-dependent
- **Preservation Austin data** (`data/preservationAustin.js`) — independent source
- **Timeline infrastructure events** (`data/timelineInfra.js`) — editorial content
- **DVI formula and weights** (`data/auditedDvi.js` computation logic) — the formula is sound, only the input data is wrong
- **UI components** — no code changes needed; they render whatever data is in the JSON files
- **Neighborhood aggregation** — method is correct, will produce correct results with correct input data
